# MeshCue · 待办

本文件只记录接下来要做的事。做完的事在版本发布时从 TODO 移进 [ROADMAP.md](ROADMAP.md)。
当前版本以 `package.json` 为准；版本判定遵守 [VERSIONING.md](VERSIONING.md)。

## 版本规划

面向实体生产的机械类模型审阅，长期迭代 1.x；所有新增字段／action 必须向后兼容，旧数据不迁移。
目标 30 FPS，以实际设备验证；不采用操作时降载、停手补回的自动降级。性能显示应可开关，展示 FPS、帧时间、三角形数。
版本规划规定顺序和范围，不是发布日期承诺；无法保持兼容的变化须单独评审。

- **1.5.1 已发布（2026-10-19）**：按需渲染、悬停分片等性能修正，NOTICE、Skill 文案与依赖更新，结论见 ROADMAP。
- **2026-10-29 重排**：实际使用中报告的界面问题插入为 1.6「审阅交互统一」；Agent 标注图层提前到 1.7；版本分支树＋特征识别顺延到 1.8，连面选择随特征识别一起（复用同一版建立的 STEP 面相邻关系）；关节与仿真依次顺延。

**排期原则**：只把技术上确定能做到的功能排进版本；交互细节未定但做得到的，照样排入。可行性未知的写进下方「远景」，不占版本号。缺陷修正、打包、文案和不改行为的重构走 patch（1.5.1、1.5.2……），不等功能版本。

### 1.5.x · 维护（下一个：1.5.2）

- **边标注被遮挡仍显示**：边标注的线与整零件标记的轮廓线现在关闭了深度测试，转到模型背面仍然可见；改为与其他标记一致，被遮挡时隐藏，同时保证不与表面闪烁、剖面与爆炸下照常裁切。（已完成：与显示边线共用下一条的按面判定。每段线在运行时从所在网格找回两侧相邻的面，只在这两个面是最前面的表面时显示；只画正面的实体上，两侧都背向视线的线段不显示；双面材质的零件上，这种线段只在它自己的面紧挨着露在最前面时显示。找相邻面的容差只按零件自身尺寸与坐标的浮点精度定，与零件离原点多远无关。标注数据不变。）已知限制：双面显示的开口薄面片，若两侧的面都背向视线、宽度又都不到一个像素，从背面看时其上本应看得见的边标注可能断断续续或不显示；整零件轮廓和显示边线不受影响。
- **显示边线偶现多余线**：开启显示边线时，偶尔出现实际不存在、像是内部本应被遮挡的线穿过平滑表面，可能随视角变化。原因未查明：先在多实体 STEP 外壳上复现、定位，再修；若与上一条同源则一并处理。（已完成：多出的线是内腔棱线，离外表面只有百分之几毫米，按深度加容差的办法都分不清。现按「像素上最前面是哪个面」判定：一条棱只在它自己相邻的面是最前面的表面时画出，与隔多远无关；表面不再加深度偏移，近平面恢复 1.5.1 的取法。回归测试 `line-occlusion` 含内外圆角不同心、最薄 0.015 mm 的外壳与圆柱面擦边的场景。）
- **分发包缺第三方许可声明**：压缩后的网页主包里 three.js、three-mesh-bvh 等依赖的版权行与许可文本被删掉，网页产物和插件包里也没有对应的许可文件。（已完成：每个打包产物旁边都有构建写出的 `THIRD_PARTY_LICENSES.md`，按打包器实际收入的模块列出各依赖的版本、许可证与许可全文，three.js 内附带的 meshoptimizer 解码器单列；网页版另附手工维护的图标与改写代码声明。npm 包在 `dist/` 里，插件包在 `web/` 与包根目录各一份。）
- 依赖小版本更新（Dependabot routine group）。
- 其他已确认、不改契约与磁盘数据的缺陷。

### 1.6 · 审阅交互统一

来自实际使用的界面反馈。只改界面交互，不改 Agent 契约与磁盘数据；属于用户可见表面的实质变化，按 VERSIONING 记 minor。交互细节未定的条目照样排入，开工时逐条确认。

- **带菜单按钮的统一点击规则**：工具类按钮（如旋转／平移、标注、爆炸）第一次点击直接进入当前子功能、马上可用，已激活时再点一次才展开菜单选其他子功能；切换显示模式类按钮（如投影方式）点一下即弹出菜单。其余带菜单按钮逐个归类，触屏上的「再点一次开菜单」开工时定。
- **填色并入图钉菜单**：填色不再单独占一个工具按钮，作为图钉展开菜单里的一项；图钉按工具类规则，一点即用当前子功能。
- **爆炸一点即展开**：点击爆炸直接展开到 100%（现在默认 0%，需手动拖滑块），滑块保留用于微调。
- **剖面按实体分色**：切口封面按实体区分颜色，相邻实体可以分辨，用于看清实体之间的配合（现在所有切口同一种颜色，只靠剖面线方向区分）。
- **标记说明确认后才生效**：说明输入框加一个确认按钮，确认前不附加到标记。回车是否等同确认、未确认就离开时丢弃／保留／提醒、修改已确认说明是否需再确认、未确认状态的提示，开工时定。
- **在 3D 视图里直接看标记说明**：再次点击标记图标展开说明，悬停弹出临时小窗，注意力不用离开三维视图；人工标记与 Agent 标记共用同一套显示（Agent 标记在 1.7 接入）。面区域标记是否补一个可点的图标、长说明的截断与滚动、同时展开几个、无说明时的表现、能否在小窗内编辑、被遮挡或转到背面时的行为，开工时定。

### 1.7 · Agent 标注图层＋GLB 收尾

- Agent 独立标注图层，用于风险和提问：Agent 发布新版本时即可附带自己的标记（点、区域、边、整零件），每处一段说明，例如「这里我改了」「这处不确定，请看」「这个尺寸请确认」。人可直接回复，样式与人类标注、理解回显区分，可一键隐藏；说明沿用 1.6 的标记说明小窗显示。检查计算由外部工具负责。
- 现有回显只能回应某一批提交、只画区域轮廓、整份只有一段总说明，不能在发布时指给人看。与回显合并还是并存、标记能否带到下一版、人能否标「已读／已处理」并回传给 Agent、打开页面时相机是否飞到第一个 Agent 标记，开工时定。新增字段／action 均为可选，旧 Agent 照常工作；Skill 与 AGENT-INTERFACE 写明何时该标、何时不该标（不把人自己的标记原样标回去）。
- 机械装配 GLB：原定压缩／量化、本地资源 `.gltf` 打包、三角带／扇、显存贴图预算已在 1.5.0 发布，不重复开发；剩余范围开工时重核。线／点维持仅提示。
- 不直接打开 3MF：Agent 先转换；多零件或多色优先 GLB，单件单色可 STL。核对并补齐 Skill 指引。

### 1.8 · 版本分支树＋特征识别＋连面选择

- 同一模型按版本树组织；从旧节点另做时保留停止推进的旧分支，分叉有标志且可重新显示。
- 底部图标时间线、游标回看、悬浮步骤说明；具体呈现与交互在本版开发时讨论。
- 版本／分支与所选旧节点的标记上下文共享给 Agent，确保修改指定旧版。
- 不自动扩展分支合并、完整 PDM 或 CAD 特征重算。
- 识别孔（含沉头、埋头）、凹槽、凸台、圆角；标记带特征并支持按特征选择。可参考 text-to-cad 的浏览器 STEP 实现，遵守 MIT 许可并保留原声明。
- 本版建立 STEP 面相邻关系，同版的连面选择复用。
- 连面选择：沿相切面一次选择整圈（如圆角）；特征边、整零件／组标记已在 1.5.0 发布，不重复实施。不加入空白处三维草图，不照搬仅存于截图的二维 Draw。

### 1.9 · 机械关节与姿态

- 声明沿用 text-to-cad 的 `{mates, couplings, poses}`：转动、滑动、圆柱副与固定，每个活动关节必须给出有限行程；联动为线性比例；姿势为命名预设。关节构成树，只做正向运动学，不含求解器。
- 关节由 Agent 随模型发布声明；Skill 与 Agent 契约同步说明写法，作为可选新增字段，旧数据照读。
- 滑杆／拖动把手查看行程，可切换和命名姿势；标记记住姿势。
- 活动／姿势下提示零件干涉；大装配先粗筛再细查，性能以实测为准。

### 1.10 · 仿真结果图层

- MeshCue 不内置求解器：温度、应力、安全系数等由 Agent 用外部工具算好，随模型发布逐点数值。
- 按数值着色并显示色标；点任意位置读数；可在热点上直接标记，Agent 读回位置与数值。
- 发光部件：显示自发光材质与辉光，Agent 可声明光源的颜色与亮度。
- 数据格式与体积上限在开工时定，守住 30 FPS 目标。

## 远景

可行性未知，不占版本号。须先验证可行，并经维护者同意，才排进版本。

- **服务端截图自查**：按指定视角、剖面、爆炸、隐藏或姿势出图，可带标记；须证明不打包 Chromium 也能出图。
- **text-to-cad 引用互通**：验证 cadgen 编号能否与 STEP 面一一对应；对应才在 `read` 附引用。
- **闭环机构**：四连杆等需要约束求解的机构。
- **从 STEP 装配约束自动读出关节**，免去 Agent 另写声明。
- **发热示意动效**：在仿真结果图层之上，为热源加热浪、扩散光晕等演示动画。
- **CFD 粒子流动**：Agent 导出流线或采样速度场，MeshCue 以粒子沿流线运动显示；须先定精简的交换格式，并验证粒子数与 30 FPS 的平衡。

## 仍未完成的零散事项

- **亚像素双面开口带的边标注可见性**：两侧面都背向视线、宽度都窄于一个像素的双面开口面片，从背面看时边标注会断续或消失。现行判定要求像素上最前面的是这条线自己的面，这么窄的面几乎盖不住像素中心；放宽容差不能解决，需要新的采样判据才能修。回归测试 `line-occlusion` 已收入这一场景并标为 `test.fail`，修好后它会报告“预期失败却通过”，届时去掉标记。
- **Dependabot PR**：核对未关闭／未合并的依赖更新，尤其历史 routine group；已落地 Vite／Three 更新不重复实施，由维护者核对 GitHub 状态后处理。
- **非标准 STL 颜色扩展**：Skill 与六语帮助已在 1.5.1 统一说明 STL 一律灰；是否支持非标准 STL 颜色扩展未定。
- **2026-09-29 CI 红灯**：`799d144` 的一次 node 失败原因未查清；再次失败先读对应日志，不凭猜测修改测试；同一工作副本不并发跑两套会改 manifest 的测试。
- **STEP 直读遗留**：BREP 面稳定锚点独立评估；测量已有面归属，不等于标记锚点完成。面数接近上限的真实模型仍缺证据，保留转换预算和帧守卫。
- **STEP 面级颜色**：评估并支持文件声明的面颜色；实体级颜色和 UTF-8 名称已修，不重复列为缺陷。
- **细分开销**：独立评估移除中点细分及缓存算法的影响，验证旧草稿兼容；源面映射不可删除，可退化为恒等映射。
- **意图回传缺口**：油漆桶选区是否可见、本地化区域名、隐藏标记提交语义，以及素色视图／选中项／滑块状态是否随批次传递，待评估；逐标记视角已在 1.4.0 完成。
- **回显确认**：审阅者是否看过／认可 Agent 回显，目前无独立回传，是否需要待定。
- **回执边界**：Agent 忙时送达观察可能停在已接纳直到读取；是否补标／再观察待评估。不增加已否决的进度层、页面计时、初步回显或宿主内直发方案。
- **Claude Code 安装**：核对 Release archive 下载／重定向、真实会话工作区和 Windows 安装体验；隔离握手与本地包测试不代替完整安装。
- **供应链**：核对 Release 制品 SHA-256 的展示及文档一致性，签名另议；继续固定 tag／commit 安装，当前约束是不改名、不转移仓库；未来确需改变，须重新评估旧路径接管风险并由维护者重新批准；更新源维持仓库元数据单一来源，不允许运行时覆盖。
- **标准浏览器矩阵**：核对支持版本，分别验证各 harness 的真实原会话回传；不把 Chrome 或一种路由验证推广到所有平台。
- **实际修改闭环**：继续验证参数化源工程修改与新版再审、人偶的实际修改／重生成路径；不承诺任意选区自动精修。
- **历史保留与回退**：按实际使用反馈完善策略；版本分支树不自动等于后台清理方案。
