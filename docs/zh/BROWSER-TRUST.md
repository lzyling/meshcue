# MeshCue · 长期记住浏览器（2026-09-10 16:32 用户定案）

**本规则取代此前60分钟绝对到期。** Kelven明确要求易用性优先：首次授予后长期记住浏览器，不按小时打断审阅。

## 正式规则

- 首次入场许可为**1小时**、一次使用（2026-09-17 由15分钟延长：窗口从 Agent 签发那一刻起算，不是从人读到带链接的消息那一刻）；新许可替换旧未用许可，已进入的浏览器不受影响。
- 浏览器授权连续30天未使用才失效。实际使用自动更新闲置截止时间，没有额外固定总时长上限。
- **⚠️ 这 30 天是授权记录的寿命，不是暴露面的寿命。** 0.11 之后，**闲置满 24 小时的实例会自我回收**、
  不再监听（`server/idle.mjs`，默认 `IDLE_HOURS = 24`）。所以一个被遗忘的审阅不是「内网上挂着一个
  带一个月信任的服务」，而是一个已经关掉的端口；重开项目会把模型、草稿、标记都恢复回来，过期的只是网址。
  轮询与编辑锁心跳**不算使用**，否则一个没人看的标签页每天四万七千次请求会让这个机制彻底失效。
  `REVIEW_IDLE_HOURS`／配置 `idleHours` 可调，**显式设为 `0` 就关掉回收**，读不懂的值回落到 24 小时而不是「永不」。
- 实际使用包括打开并核对模型、旋转／缩放／点击／键盘等可见页面操作、保存标注、接续／结束审阅、下载当前模型。前端交互续期节流至每分钟一次；后台状态轮询和编辑锁心跳不续期。
- 刷新、关闭再打开同一浏览器，以及服务重启后保留授权。新标签页共享浏览器授权，但独立遵守编辑视窗／锁，不允许覆盖另一视窗的草稿。
- 同来源范围内发布新版或结束一轮审阅，不退出浏览器。来源／项目授权范围改变仍撤回旧范围权限；不同项目不共用授权库。
- IP只约束首次定向领取。已有cookie不因客户端局域网IP变化失效；换浏览器／清除cookie需要重新领取。
- 主动撤销浏览器或全部授权不删除模型、草稿、已提交批次或编辑锁。

## Agent 管理

使用当前实例的 `REVIEW_DATA_DIR`，不要误指正式runtime：

```sh
node scripts/reviewctl.mjs browsers
node scripts/reviewctl.mjs revoke <browser-record-id>
node scripts/reviewctl.mjs revoke
```

0.9 之后 `reviewctl` 只是三个入口之一，后面两个才是给别的 harness 用的正常路径：
`meshcue` CLI（JSON 进 JSON 出）与 `meshcue-mcp`（stdio MCP server）。三者走的是同一个 manager，
本节规则与它们完全一致。

`browsers`只返回非凭据记录ID、归纳的浏览器标签、最近内网地址、创建／使用／到期时间与视窗数量。记录ID只能用于本机管理查询与撤销，不可用于登录。按已知设备与记录定位，多个无法区分的浏览器不盲目全撤。无参数revoke为撤销全部；撤销操作同时取消未用入场许可，防止自动重新领取。

## 实现边界

- 浏览器持有 HttpOnly／SameSite=Strict 的持久cookie；实际使用时刷新其Max-Age。当前LAN HTTP不是TLS。
- 服务器的 `browser-access.json` 只保存不可直接登录的SHA-256校验摘要、来源范围、时间及视窗关联，**不保存明文cookie／入场许可**，也不在管理响应中返回摘要。文件0600、原子替换，不进Git；未用入场许可仍仅在内存，服务重启后不保留。
- 原记录损坏则明确报错且不覆写。持久写入失败时回滚内存授权状态并返回失败，不把失败的撤销说成成功。
- 长期使用不会积累到旧的16个历史视窗上限：每个浏览器保留至多64个关联，新增时淘汰最早的非锁持有者，始终保留当前草稿锁对应的视窗。
- **（历史，已不适用）** 旧60分钟实现没有保存浏览器校验记录，首次升级无法直接从磁盘恢复旧授权。仅对已核对且获准的Windows测试地址做过一次自动接续发放；那是 0.4→0.5 那次一次性迁移，代码里早已没有这条路径。不读取浏览器cookie到聊天或临时脚本输出。

## 验证

注入时钟验证15分钟入场边界、30天闲置边界、实际使用滑动续期和轮询不续期。真实HTTP测试重启整个进程后恢复同一浏览器／视窗／草稿锁，并验证单浏览器撤销后其它浏览器仍有效。浏览器测试覆盖普通HTTP自动领取、模型操作、刷新与重开标签页、进程重启、多标签页共享cookie恢复及跨来源隔离。

这些是隔离验收；Windows用户的可见操作和真实Telegram回复仍需实际观察，不以cookie存在或Mac测试代替。
